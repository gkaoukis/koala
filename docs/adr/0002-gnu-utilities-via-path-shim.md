# GNU utilities on macOS via a private PATH shim, not env-var indirection

Benchmark scripts (~90 files across 18 benchmarks) call GNU-flavored `sed`/`grep`/`find`/`awk` directly (e.g. `sed -i` without a backup suffix, `grep -P`, `date -d`). macOS ships BSD variants of these with different flag semantics, which risks breaking `validate.sh`'s hash-based output comparisons if behavior differs even slightly.

**Decision**: On macOS, install real GNU coreutils/sed/grep/findutils/gawk via Homebrew, then create a private shim directory (e.g. `$TOP/.tools/gnubin`) containing symlinks with plain names (`sed` → `gsed`, `grep` → `ggrep`, `find` → `gfind`, `awk` → `gawk`, …), and prepend that directory to `$PATH`. Benchmark scripts keep calling bare `sed`/`grep`/`find` unmodified — no edits to the ~90 `scripts/*.sh` files. `$PATH` is never modified globally (no edits to shell rc files, no symlinks into `/usr/local/bin`); each of the five stage scripts (`install.sh`/`fetch.sh`/`execute.sh`/`validate.sh`/`clean.sh`) sets it up independently at the top of the script, scoping the change to that process and its children for the duration of one run.

This also transparently covers whatever interpreter `$KOALA_SHELL` points at: `execute.sh` exports the modified `PATH` before spawning `$KOALA_SHELL "$BENCHMARK_SCRIPT"`, so any interpreter under test (bash, dash, zsh, an experimental research shell, PaSh) inherits it via normal process inheritance — command-name-to-binary resolution via `PATH` happens at the OS/libc level (`execvp`), not something shells reimplement, so this isn't bash-specific.

**Why chosen over env-var indirection** (`$SED`/`$GREP`/`$FIND` that scripts call explicitly): env vars would require auditing and editing all ~90 benchmark scripts, versus zero edits with the PATH-shim approach.

**Fallback**: env-var indirection is kept as an escape hatch for the cases PATH substitution can't reach — chiefly, any script that invokes a utility by hardcoded absolute path (e.g. `/usr/bin/find`) rather than bare command name, since that skips `PATH` lookup entirely. No exhaustive audit for these was done upfront; they'll be identified and patched individually as they're found during implementation.

**Explicitly out of scope**: macOS's stock `/bin/bash` is version 3.2 (pre-GPLv3) and lacks bash-4+ features (`declare -A`, `mapfile`, …) that at least one stage script (`web-search/validate.sh`) uses. This is unrelated to the coreutils/PATH problem — that script always runs as itself, never swapped via `$KOALA_SHELL` — and is being fixed as an isolated portability bug (rewritten to avoid bash-4-only syntax), not by adding any bash-version-resolution mechanism to `$PATH`. Forcing a specific newer bash onto `$PATH` was considered and rejected, since it would interfere with `$KOALA_SHELL`'s purpose of letting a researcher swap in an arbitrary interpreter under test.
